# TeamSync — how this repository collaborates

Generated by `teamsync init`. Replace this guidance with your team's real
agreements — it is yours now.

## Roles and advisory ownership

| Role | Owns (advisory) | Coordinate before touching |
| --- | --- | --- |
| services | `services/**` | `packages/contracts/**` |
| backend | `apps/backend/**` | `packages/contracts/**`, lockfiles |
| frontend | `apps/frontend/**` | `packages/contracts/**`, lockfiles |
| qa | `tests/**`, `.github/workflows/**` | everything under test |

Role ownership is **advisory** — it guides where you work and powers warnings
on `teamsync submit`. It is not access control; GitHub permissions decide who
can push where. Shared paths (contracts, lockfiles, root config, workflows)
belong to everyone: change them in small PRs and say so in the description.

## Daily flow

```sh
teamsync start my-task        # unique branch teamsync/<login>/<role>/my-task-<suffix>
# …work in any editor…
teamsync submit --all -m "Add my feature"   # stage → commit → push → PR
teamsync status               # PR states, checks, conflicts
teamsync watch                # poll until merged (read-only)
teamsync sync                 # update from the default branch
```

Independent changes merge automatically **after required checks pass** via
GitHub-native auto-merge. Conflicting changes stay blocked until a human
resolves them locally with `teamsync sync`.

## Repository settings an admin must apply once

TeamSync never changes repository settings silently. An admin should:

1. **Enable auto-merge**: Settings → General → Pull Requests → ✅ Allow auto-merge.
2. **Protect the default branch**: Settings → Branches → Add rule:
   - Require a pull request before merging.
   - Require status checks: select **`integration`** (the aggregate gate from
     `.github/workflows/integration.yml`).
   - ✅ Require branches to be up to date before merging.
3. **Actions**: enabled, with default workflow permissions set to
   **read repository contents** (least privilege). The provided workflow
   already declares minimal per-job permissions.
4. Optional (paid plans): a **merge queue** on the default branch. TeamSync
   detects it and lets GitHub queue PRs; keep CI triggering on merge-group
   events (comment is in the workflow file).

## When things conflict

- `teamsync status` shows which PRs are in conflict or behind.
- Run `teamsync sync` on your task branch: it merges the updated base into
  your branch (never rewrites history) and, on conflict, aborts cleanly and
  lists the affected files for you to resolve deliberately.
- Push the resolution with `teamsync submit` — the same PR is reused.
